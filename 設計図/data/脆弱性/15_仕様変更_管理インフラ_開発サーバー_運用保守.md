## 1. 背景と目的

先の網羅的セキュリティ監査（`05_インフラ_依存関係_設定脆弱性分析.md`）において、ローカル管理サーバーの外部露出および任意コード注入（CRITICAL）、Firebase Hosting 設定およびHTTPセキュリティヘッダーの完全欠落（HIGH）、Cloud Storage CORS設定の過剰開放（HIGH）、破壊的運用スクリプトの安全弁欠如（CRITICAL）、ならびに依存ライブラリにおける多数の既知脆弱性（CRITICAL）が検出された。

文化祭本番では、学校内Wi-Fiや来場者モバイル回線など、信頼できない端末が同一ネットワークに多数存在する。本設計書は、これらの脆弱性を根本から根絶し、文化祭本番運用における安全性を物理的・論理的に保証するための確定仕様変更内容を定義する。

### 基本方針
1. **Zero-Trust & Localhost Isolation**: ローカルツールは外部ネットワークから完全に不可視・アクセス遮断とする。
2. **Strict Sanitization & Code-as-Data Separation**: データ保存処理においてコードとデータを厳格に分離し、任意のスクリプト挿入を物理的に排除する。
3. **Defense-in-Depth (多層防御)**: Hosting層でのセキュリティヘッダー（CSP, HSTS, X-Frame-Options等）およびStorage層でのCORS最小権限化を徹底する。
4. **Fail-Safe Defaults (安全第一の運用スクリプト)**: 本番データを変更・削除するスクリプトには、二重の手動入力確認および環境変数ガードを義務付ける。

## 2. 仕様変更 1: ローカル管理サーバー (`admin-server.js` / `test-admin-server.js`)

### 2.1 課題と改修方針
- **課題**: `app.listen(port)` が `0.0.0.0` で全インターフェースにバインドされ校内LANから丸見えであること、認証が一切ないこと、`req.body.version` を未エスケープで埋め込んでおり Stored XSS / サプライチェーン汚染が引き起こせること。
- **改修方針**:
  - `127.0.0.1` への固定バインドを強制（外部インターフェース露出の完全遮断）。
  - セッショントークン認証（`x-admin-token`）を導入。
  - `Origin` / `Host` ヘッダーを厳格検証し、ローカルCSRFおよびDNS Rebindingを完全防御。
  - `data.js` の生成ロジックにおいて、テンプレートリテラル展開を完全廃止し、`JSON.stringify` と正規表現エスケープによる安全なシリアライズを適用。
  - 変更直前ファイルの自動バックアップおよびアトミック書き込み（一時ファイル作成 → rename）を導入。

### 2.2 確定改修仕様 (`admin-server.js`)

```javascript
/**
 * Nanryosai 2026 - Master Data Admin Local Server
 * File: admin-server.js
 * Security Hardened: v0.6.0
 */
const express = require("express");
const fs = require("fs");
const path = require("path");
const crypto = require("crypto");

const app = express();
const PORT = 3001;
const HOST = "127.0.0.1"; // ★ 127.0.0.1 厳格固定 (0.0.0.0 を完全排除)

// 1. サーバー起動ごとにセキュアなランダムAPIトークンを生成（または環境変数から取得）
const ADMIN_API_TOKEN = process.env.ADMIN_SERVER_SECRET || crypto.randomBytes(32).toString("hex");

// 2. ペイロード上限を必要最小限（5MB）に設定
app.use(express.json({ limit: "5mb" }));

// 3. セキュリティミドルウェア: Host / Origin / 認証ヘッダーの厳格検証
app.use((req, res, next) => {
  const host = req.headers.host;
  // DNS Rebinding 防止: localhost または 127.0.0.1 以外の Host を完全拒否
  if (!host || (!host.startsWith("localhost:") && !host.startsWith("127.0.0.1:"))) {
    return res.status(403).json({ error: "Forbidden: Invalid Host header (DNS Rebinding protection)" });
  }

  // APIエンドポイントの防御
  if (req.path.startsWith("/api/")) {
    const origin = req.headers.origin;
    // ローカルOriginのみ許可 (CSRF防止)
    if (origin && origin !== `http://localhost:${PORT}` && origin !== `http://127.0.0.1:${PORT}`) {
      return res.status(403).json({ error: "Forbidden: Cross-Origin Request Blocked" });
    }

    // 認証トークンの検証
    const clientToken = req.headers["x-admin-token"];
    if (!clientToken || clientToken !== ADMIN_API_TOKEN) {
      return res.status(401).json({ error: "Unauthorized: Missing or invalid x-admin-token header" });
    }
  }

  // セキュリティヘッダーの付与
  res.setHeader("X-Content-Type-Options", "nosniff");
  res.setHeader("X-Frame-Options", "DENY");
  res.setHeader("Cache-Control", "no-store, no-cache, must-revalidate, proxy-revalidate");
  res.setHeader("Pragma", "no-cache");
  res.setHeader("Expires", "0");
  next();
});

// 4. 静的ファイル配信 (mainディレクトリ)
app.use(express.static(path.join(__dirname, "main")));

// 5. 安全な data.js 保存API
app.post("/api/save-data", (req, res) => {
  try {
    const { projectData, stageData, version } = req.body;

    // データ型の厳格バリデーション
    if (!Array.isArray(projectData)) {
      return res.status(400).json({ error: "Invalid payload: projectData must be an array" });
    }
    if (!Array.isArray(stageData)) {
      return res.status(400).json({ error: "Invalid payload: stageData must be an array" });
    }

    // version パラメータのサニタイズ（英数字・ハイフン・ドット・アンダースコアのみ許可）
    const rawVersion = String(version || Date.now());
    const safeVersion = rawVersion.replace(/[^a-zA-Z0-9.\-_]/g, "");
    if (!safeVersion) {
      return res.status(400).json({ error: "Invalid version format" });
    }

    const filePath = path.join(__dirname, "main", "data", "data.js");
    const backupDir = path.join(__dirname, "main", "data", "backups");
    if (!fs.existsSync(backupDir)) {
      fs.mkdirSync(backupDir, { recursive: true });
    }

    // 直前バックアップの作成 (data.backup.<timestamp>.js)
    if (fs.existsSync(filePath)) {
      const backupFile = path.join(backupDir, `data.backup.${Date.now()}.js`);
      fs.copyFileSync(filePath, backupFile);
    }

    // JSONシリアライズ時の安全化 (HTMLタグ・スクリプトタグの無害化: < を \u003c にエスケープ)
    const safeProjectDataJson = JSON.stringify(projectData, null, 2).replace(/</g, "\\u003c");
    const safeStageDataJson = JSON.stringify(stageData, null, 2).replace(/</g, "\\u003c");
    const safeVersionLiteral = JSON.stringify(safeVersion);

    // ソースコードの組み立て (文字列連結ではなく JSON.stringify を通した値のみ配置)
    const fileContent = `/**
 * Nanryosai 2026 Master Data
 * Version: ${safeVersion}
 * Last Modified: ${new Date().toISOString().split("T")[0]}
 * Author: Nanryosai 2026 Project Team (Auto-generated)
 */
console.log("data.js loading...");

// バージョン情報 (admin_syncで同期状態を確認するために使用)
const dataVersion = ${safeVersionLiteral};

// 企画の名簿データ
const projectData = ${safeProjectDataJson};

// ステージデータ (出演スケジュール)
const stageData = ${safeStageDataJson};

console.log("data.js loaded: projectData count =", projectData.length, "version =", dataVersion);
console.log("data.js loaded: stageData count =", stageData.length);

// グローバルアクセス用に window オブジェクトに紐付け
window.projectData = projectData;
window.stageData = stageData;
`;

    // アトミック書き込み: 一時ファイルに保存後、アトミックにリプレイス
    const tempPath = `${filePath}.tmp.${Date.now()}`;
    fs.writeFileSync(tempPath, fileContent, "utf8");
    fs.renameSync(tempPath, filePath);

    console.log(`[Admin Server] Successfully saved data.js (Version: ${safeVersion})`);
    res.json({ message: "Success: data.js updated locally with full integrity." });
  } catch (error) {
    console.error("[Admin Server] Save Error:", error);
    res.status(500).json({ error: error.message });
  }
});

// 6. 127.0.0.1 へのバインド起動
app.listen(PORT, HOST, () => {
  console.log(`
==================================================
 南陵祭'26 管理用ローカルサーバー (Secure Mode)
 Running at: http://${HOST}:${PORT}/admin_sync.html
```

## 3. 仕様変更 2: ホスティングセキュリティヘッダー仕様 (`firebase.json`)

### 3.1 課題と改修方針
- **課題**: `firebase.json` に `"hosting"` 定義が完全に欠落しており、誤デプロイ時にリポジトリ内の全ファイル（スクリプト・設定）が丸見えになる危険性があること、およびブラウザ保護ヘッダー（CSP, HSTS, X-Frame-Options等）が一切未設定であること。
- **改修方針**:
  - `firebase.json` に `"hosting"` 設定を新設。
  - 公開対象ディレクトリを明示し、`scripts/`, `functions/`, `admin-server.js`, `*.log`, `package.json` 等を `ignore` リストで物理的に遮断。
  - すべてのリクエストに対して最高水準のHTTPセキュリティヘッダーを付与。
  - 動的HTMLと静的アセットで適切な `Cache-Control` を分離設定。

## 4. 仕様変更 3: Cloud Storage CORS設定の最小権限化 (`cors.json`)

### 4.1 課題と改修方針
- **課題**: `origin: ["*"]` に対して `PUT`, `POST`, `DELETE` メソッドが全開放されており、第三者Webサイトからの悪意あるブラウザ経由リクエストを受け付ける余地がある。
- **改修方針**:
  - 来場者向けの商品写真表示（`GET`, `HEAD`）のみ全オリジン（`*`）に開放。
  - 画像アップロード・更新（`PUT`, `POST`）は、本番ドメインおよびローカル検証ドメインに限定。
  - `DELETE` はブラウザ直接呼出を禁止（Cloud Functions または管理者ポータル経由の特定処理のみに限定し、CORSメソッドから除外）。

## 5. 仕様変更 4: 破壊的運用スクリプトのフェイルセーフ仕様

### 5.1 課題と改修方針
- **課題**: `cleanupAndSyncOfficialData.js`, `resetTestData.js`, `wipeAuthUsers.js` は、実行すると確認なしで本番Firestore、Storage、Authユーザーを一括完全消去する極めて危険な実装である。
- **改修方針**:
  1. **プロジェクトID手動入力ガード**: 破壊的処理の前に、ターミナルで対象のプロジェクトID（`nanryosai-2026-a4091`）および確認フレーズ（`DELETE_CONFIRMED`）の直接手入力を要求する。
  2. **環境変数安全弁**: `ALLOW_DESTRUCTIVE_OPERATIONS=true` がセットされていない場合は即時終了。
  3. **認証情報の安全化**: `firebase-tools.json` の直接読み込みを廃止し、Google Cloud標準の ADC（Application Default Credentials）または明示的なサービスアカウントキーファイル指定に統一。
  4. **`generate_hash.js` / `setupVenueAdmin.js`**: 平文引数渡しを廃止し、対話型非表示プロンプト入力に変更。PBKDF2の反復回数をOWASP推奨の 210,000回 へ引き上げ。

### 5.2 運用スクリプト共通安全確認モジュール仕様 (`scripts/lib/confirmGuard.js`)

```javascript
/**
 * 破壊的運用スクリプト用 共通安全弁モジュール
 * scripts/lib/confirmGuard.js
 */
const readline = require("readline");

async function assertDestructiveOperationAllowed(targetProjectId, operationName) {
  // ガード1: 明示的な環境変数フラグ
  if (process.env.ALLOW_DESTRUCTIVE_OPERATIONS !== "true") {
    console.error(`
🚨 [SAFETY GUARD ERROR] 破壊的処理 "${operationName}" の実行がブロックされました。
本処理を実行するには環境変数 'ALLOW_DESTRUCTIVE_OPERATIONS=true' を設定してください。
`);
    process.exit(1);
  }

  // ガード2: 対話型コンソール入力でのプロジェクトIDおよび確認フレーズ照合
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout,
  });

  const prompt = (query) => new Promise((resolve) => rl.question(query, resolve));

  console.log(`
⚠️=========================================================⚠️
【警告】これから本番データの一括消去・初期化を実行します。
対象プロジェクト: ${targetProjectId}
操作内容: ${operationName}
⚠️=========================================================⚠️
`);

  const inputProjectId = await prompt(`確認のため、対象プロジェクトID [${targetProjectId}] を正確に入力してください: `);
  if (inputProjectId.trim() !== targetProjectId) {
    console.error("❌ プロジェクトIDが一致しません。処理を中断しました。");
    rl.close();
    process.exit(1);
  }

  const confirmPhrase = "DELETE_ALL_DATA_NOW";
  const inputPhrase = await prompt(`最終確認です。消去を承認する場合は [${confirmPhrase}] と入力してください: `);
  rl.close();

  if (inputPhrase.trim() !== confirmPhrase) {
    console.error("❌ 確認フレーズが一致しません。処理を中断しました。");
    process.exit(1);
  }

  console.log("✅ 安全確認が完了しました。処理を続行します...\n");
}

module.exports = { assertDestructiveOperationAllowed };
```

### 5.4 `generate_hash.js` 改修仕様 (OWASP準拠)

```javascript
const crypto = require("crypto");
const readline = require("readline");

const ITERATIONS = 210000; // ★ OWASP推奨基準 (210,000回) に引き上げ
const KEY_LEN = 64;
const DIGEST = "sha512";

function hashPassword(password, salt) {
  const generatedSalt = salt || crypto.randomBytes(16).toString("hex");
  const derivedKey = crypto.pbkdf2Sync(password, generatedSalt, ITERATIONS, KEY_LEN, DIGEST).toString("hex");
  return { derivedKey, salt: generatedSalt };
}

const rl = readline.createInterface({
  input: process.stdin,
  output: process.stdout,
});

// コマンドライン引数（process.argv）での平文受付を禁止し、対話プロンプトで取得
rl.question("ハッシュ化するパスワードを入力してください (画面に表示されません): ", (password) => {
  rl.close();
  if (!password || password.length < 8) {
    console.error("エラー: パスワードは8文字以上で入力してください。");
    process.exit(1);
  }

  const { derivedKey, salt } = hashPassword(password);
  console.log("\n[ハッシュ生成完了]");
  console.log(JSON.stringify({ hash: derivedKey, salt: salt, iterations: ITERATIONS }, null, 2));
});
```

## 6. 仕様変更 5: 依存パッケージ（CVE）解消手順および固定仕様

### 6.1 課題と改修方針
- **課題**: `protobufjs`（RCE/コードガジェット）、`websocket-driver`（メッセージ破壊/リソース制限バイパス）、`jws`（HMAC署名検証不備）など、計37件の既知脆弱性が放置されている。
- **改修方針**:

## 7. 実装・検証チェックリスト (Implementation Checklist)

本仕様変更の実装担当者は、各タスク完了時に以下の項目をすべて確認すること。

- [ ] **1. `admin-server.js` の堅牢化**
  - [ ] `HOST = "127.0.0.1"` が指定され、外部IPや `0.0.0.0` からの接続が拒否されることを確認。
  - [ ] `x-admin-token` ヘッダーがないリクエストが `401 Unauthorized` で遮断されることを確認。
  - [ ] 不正な `Origin` / `Host` ヘッダーを付与したリクエストが `403 Forbidden` となることを確認。
  - [ ] `version` パラメータに `"; alert(1); //` 等のコードを含めてPOSTした際、サニタイズされ安全に保存される（コード実行が起きない）ことを確認。

  - [ ] `test-admin-server.js` が削除されたことを確認。
- [ ] **2. `firebase.json` のセキュリティヘッダー**

  - [ ] デプロイまたはエミュレータ起動時に、ブラウザのレスポンスヘッダーに CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy が返却されることを確認。

# 南陵祭2026 開催後データ分析・収集要件

開催後のデータ分析において、必要なデータを収集するための要件定義です。

## A. 注文生ログ（Firestore `orders` コレクション）— 最重要・全ての土台

**大原則：** 開催後、集計する前に `orders` コレクション全件を生のままエクスポートして保全してください。個人情報削除ポリシー（3ヶ月以内削除）があるため、削除前に必ず匿名化した生データを確保します。これが無いと後述の分析が一切できません。

各注文ドキュメントから取得すべき基礎項目：

- `orderId`
- `orderChannel`（mobile / sok / pos）
- `storeId`（店舗別集計の軸）
- `status`（最終ステータス：completed / cancelled / abandoned）
- `receiptNumber`
- `items`（商品ごとの itemId, name, price, quantity, customizations）
- `totalPrice`
- `userId`（匿名化した上で、リピート判定に使用）
- `createdBy`（POS操作スタッフ、店舗別の担当分析に使用）
- `cancellationReason`
- **全タイムスタンプ**（処理時間分析の生命線。全て揃っていることを開催後すぐに確認すること）：
  - `createdAt`
  - `readyToServeAt`
  - `readyForPickupAt`
  - `completedAt`
  - `cancelledAt`
  - `abandonedAt`
  - `termsAgreedAt`
  - `sokClaimedAt`
  - `sokConfirmedAt`
  - `expiredAt`

## B. 注文集計指標（Aから算出）

### B-1. ボリューム系
- 総注文数（全体・経路別・店舗別・日別・時間帯別）
- 総売上（全体・経路別・店舗別・日別・時間帯別）
- 平均単価（売上÷注文数、各軸で算出）
- 商品別販売数ランキング
- 商品別売上ランキング
- トッピング/カスタマイズの選択率
- 1注文あたり平均商品点数
- 時間帯別注文数（1時間刻み、できれば30分刻み）
- ピーク時刻の特定（分単位で最も注文が集中した瞬間）

### B-2. 転帰（結末）系
- ステータス別件数（completed / cancelled / abandoned）
- キャンセル率（全体・経路別・店舗別）
- キャンセル理由の内訳（`cancellationReason` 集計）
- 放置率（abandoned÷全体、経路別）
- SOK失効率（expired÷SOK仮注文数）

### B-3. 処理時間系（タイムスタンプ差分）
**※上記すべてを店舗別・時間帯別にも分解する。また、平均だけでなく分布（ヒストグラム用の全データ点）を見て「たまに異常に遅い注文」を可視化すること。**

- **調理時間**：`createdAt` → `readyToServeAt`（平均/中央値/最大/最小、平常時とピーク時）
- **提供口準備時間**：`readyToServeAt` → `readyForPickupAt`
- **受取待ち時間**：`readyForPickupAt` → `completedAt`
- **注文総所要時間**：`createdAt` → `completedAt`
- **SOK claim所要**：`createdAt` → `sokClaimedAt`
- **SOK確定所要**：`sokClaimedAt` → `sokConfirmedAt`

### B-4. リピート・ユーザー系
- ユニーク注文者数（匿名化 `userId` のユニークカウント）
- リピート注文率（複数回注文した `userId` の割合）
- 1人あたり平均注文回数・平均支払額
- リピーターの経路（例：初回モバイル→2回目も？）

## C. Googleアナリティクス — Web行動データ

**※開催前に必ず設定を完了させ、主要ステップにイベント計測を仕込んでおくことが絶対条件です。仕込み忘れると後から絶対に取れません。**

### C-1. 基礎トラフィック
- 総PV・総セッション数
- ユニークユーザー数
- 日別・時間帯別のアクセス推移
- 新規/リピート訪問比率
- 平均セッション時間
- 直帰率

### C-2. デバイス・環境
- デバイス種別（スマホ/タブレット/PC）
- OS内訳（iOS / Android）
- ブラウザ内訳（Safari / Chrome など）— Push通知やポップアップ挙動の分析に有効
- 画面解像度分布

### C-3. 流入経路
- 参照元（QRコード直打ち / 公式サイトリンク / SNS / 検索）
- **QRコード設置場所別の流入**（設置場所ごとにURLパラメータを変えておけば計測可能。★事前設計が必須）
- ランディングページ内訳

### C-4. ページ別・導線
- ページ別PV（index / mobile-order / status / sok など各画面）
- モバイルオーダー画面到達数
- 画面遷移フロー（どこから来てどこへ行ったか）

### C-5. コンバージョンファネル（★事前設定必須）
各ステップをGAイベントとして計測し、各段階の通過率・離脱率を算出します（ファネル図の元データ）。※イベントを仕込まないとファネルが描けません。最優先で事前設定を。
- サイト訪問
- モバイルオーダー画面到達
- ログインボタン押下
- ログイン完了
- 店舗選択
- カート投入
- 注文確定

## D. 通知・認証・セキュリティ（Firestore `users` / `banned_users` + Functionsログ）

- FCM通知許可率（`users.notificationEnabled` / `permissionStatus` 集計）
- `permissionStatus` 内訳（granted / denied / default / skipped / unsupported）
- `deviceType` 内訳（ios_or_mac / other）
- Push送信数・（可能なら）到達/クリック数
- BAN発火総数（`banned_users` 件数）
- BAN理由内訳（abandoned_order / manual_ban）
- 誤BAN申し出件数・手動解除件数（※人的記録）
- App Check遮断件数（Firebase Console / Functionsログ）
- ドメイン制限による拒否件数（※★事前にログイン時のログ出力を仕込むことで取得可能）
- 認証成功/失敗回数

## E. インフラ・コスト（Firebase Console / GCP）

- Firestore 読み取り/書き込み/削除回数（日別・ピーク時）
- Cloud Functions 呼び出し回数（関数別）
- Cloud Functions 実行時間・エラー率（関数別）
- Cloud Functions コールドスタート発生状況
- Cloud Storage 転送量・保存容量
- 各サービスの無料枠に対する消費率
- 実際の課金額（★仮に無料枠内でも「もし有料なら」の試算があると価値が出る）
- Scheduled Function（`abandonStaleOrders` 等）の実行ログ・処理件数

## F. 当日限定・人的観測 — ★逃すと二度と取れない最重要カテゴリ

**※システムログは後で取れますが、以下はその場でメモ・撮影しないと消えます。担当者を決めて記録係を1人立てることを強く推奨します。**

### F-1. タイムスタンプ付き出来事ログ
- 各トラブルの発生時刻・検知時刻・対応開始・復旧時刻（時系列表の元データ）
- 誰がどう判断したか（テザリング切替の判断、紙運用検討の有無など）
- サポート対応の1件ごとの記録（時刻・内容・対応・所要時間）

### F-2. 写真・動画（報告書のビジュアルの核）
- 各店舗の設置状況（SOK端末、AirPay QR掲示、モニター）
- 呼び出しモニター（`monitor.html`）の実表示画面
- 行列の様子（ピーク時・閑散時の対比があると効果的）
- 提供口での受け渡し風景
- 厨房の `kitchen.html` 稼働画面
- スタッフの実際の操作風景
- トラブル対応中の様子
- 各画面の実スクリーンショット（当日の実データが入った状態のもの）

### F-3. 定性観測メモ
- SOKで来場者が迷ったポイント（具体的にどのステップで手が止まったか）
- 来場者の生の声（「便利」「わかりにくい」など、聞こえた言葉をそのまま）
- スタッフが感じた負荷の高い瞬間
- 想定外の使われ方（意図しない操作、予想外の質問）
- 金額照合が省略された場面の頻度感（記録係の主観でよい）

### F-4. 環境・外部要因
- 天候（来場者数・行動に影響）
- 来場者総数（学校の公式カウント）
- 各時間帯の校内混雑度
- 校内Wi-Fiの体感的な調子

## G. スタッフ・来場者アンケート — ★開催後すぐ実施
**※記憶が新しいうちに取る。開催の翌週まで。**

### G-1. 利用団体スタッフ向け
- 使いやすかった画面・使いにくかった画面
- トレーニングは十分だったか
- 紙運用と比べてどうだったか
- 一番困った瞬間
- 来年も使いたいか
- 改善してほしい点（自由記述）

### G-2. 来場者向け（可能なら）
- どの経路で注文したか
- 操作は簡単だったか
- 待ち時間は許容範囲だったか
- また使いたいか
- SOK利用者に：どこで迷ったか

## H. 前年比較データ — 差分を語る材料

**※去年（`lastyear/` にアーカイブあり）の紙運用と比較すると報告書の説得力が跳ね上がります。**
- 前年の集計作業所要時間 vs 今年（実質ゼロ）
- 前年の行列の長さ/待ち時間の体感 vs 今年
- 前年の注文ミス発生の体感 vs 今年
- 前年の売上規模（比較の分母として）
- 前年の現金取扱トラブル vs 今年（ゼロ）
- 去年のデータが乏しくても「去年は記録すら残っていない、それ自体が紙運用の限界」という論点になります。

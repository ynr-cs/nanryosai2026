- [ ] `status: "cooking"` で保存されていること（旧: `"authorized"` や `"unpaid_at_pos"` ではない）
- [ ] `orderChannel: "mobile"` が存在すること
- [ ] `receiptNumber` が 7000 番台の番号であること
- [ ] `userId` に注文者のUIDが入っていること

**確認手順**: 複数の端末から同時に注文を行うか、連続して注文ボタンを押下する。

### D. Firestore セキュリティルール

**確認手順 (ブラウザの開発者コンソール)**:

- [ ] **orders への write 禁止**: DevTools コンソールで Firestore SDK から直接 `orders` コレクションへの `add()` や `set()` を試みると「permission-denied」エラーになること
- [ ] **自身の注文は read 可能**: `status.html?orderId=自分の注文ID` にアクセスすると注文が表示されること
- [ ] **他人の注文は read 不可**: 別アカウントの `orderId` を URL に直接入力するとアクセスできずエラーになること
- [ ] **ready_for_pickup の注文は誰でも read 可能**: 未ログイン状態でも `monitor.html` に `ready_for_pickup` の注文番号が表示されること

### E. BANチェック

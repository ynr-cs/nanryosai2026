# デザインシステム・UIガイドライン

## 1. 基本方針

南陵祭ポータル・POSシステムは、学校祭当日の多忙な環境下での操作を想定し、**「直感性」「視認性」「モバイルファースト」**をデザインの核心としています。

---

## 2. 共通コンポーネント仕様

### 入力フィールド (`.input-field`)

- **高さ**: `44px` (Apple HIG 推奨の最小タッチターゲット)
- **パディング**: `0 12px`
- **フォントサイズ**: `0.95rem` (モバイルでの `16px` 未満による iOS 自動ズーム防止のため、実際のレンダリングは `16px` を基準とする)
- **配色**:
  - 背景: `#f9fafb` (薄いグレー)
  - 文字色: `#1f2937` (濃いグレー、青文字などは避ける)
  - ボーダー: `#d1d5db`

### パスワード入力フィールド (POS共通)

- **基本仕様**: `type="password"` を基本とし、モバイルでの利便性向上のため `inputmode="numeric"` および `pattern="[0-9]*"` を指定して数字キーボードを優先表示する。
- **入力制御**: `input` イベントにおいて、全角英数字を半角に自動変換し、英数字以外の文字を自動削除する。
- **プレビュー機能**: 専用のラッパーとトグルボタン（目玉アイコン）を使用し、パスワードの表示と非表示を切り替えられるようにする。

### ボタン

- **基本サイズ**: 44px 以上の高さを確保。
- **フィードバック**: `:hover` での背景変化、および通信中の `disabled` 制御を必須とする。

## 3. レスポンシブ & デバイス対応

### Viewport 設定

iOSデバイスにおける画面回転（ランドスケープ⇔ポートレート）時の意図しないズームを防ぐため、以下のメタタグを基本とする。

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0, maximum-scale=1.0"
/>
```

### iPad / タブレット対応 (1024px Breakpoint)

- **サイドバー**: モバイル版と同様のボトムナビゲーションに切り替え。
- **グリッドレイアウト**:
  - 3カラムレイアウトは 1024px 以下で **2カラム** （または 1カラム）に可変させる。
  - 例：検索フォームでは、キーワード入力を全幅 (`1 / -1`) とし、日付・ステータスを横並びにする。

### モバイル対応 (768px Breakpoint)

- **テーブル表示**: 水平スクロールを避け、カード形式（スタック表示）への変換を推奨。
- **タッチターゲット**: すべてのクリック要素において、隣接要素との十分なマージン（`gap: 12px` 以上）を確保。
- **オーバーレイメニュー**: 
  - 全画面（または半画面）のメニューを開く際は、下部パディングに `var(--safe-area-bottom)` を必ず含めること。
  - コンテンツのオーバーフローに備え、`overflow-y: auto` を設定すること。

## 5. 運用フローのUIパターン

### POS QR決済フロー (キャッシュレス)

- **モニター画面**: 決済方法が `"pos"` の場合、QRコード提示とともに「スタッフに完了画面を提示」するよう赤字等で強調する。
- **提供画面 (Presenter)**: オペレーションの単純化のため、完了アクションは単一の大型ボタン（横幅100%）に集約する。
- **完了フィードバック**: モニターの完了画面はグローバル対応および視認性を考慮し、"Thank you" 表記を基本とする。

## 6. ログイン・初期ロード画面の統一仕様

### 初期状態は「ローディング」
- 認証を要するすべての画面（`portal.html`、`pos.html`、`kitchen.html` 等）は、HTMLの初期状態でログインUIやメインコンテンツを非表示にし、画面全体を覆うローディング（`<div id="global-loader" class="active">`）を表示すること。
- これは、認証チェックが完了する前に未ログイン画面が一瞬表示されてしまう（チラつき）のを防ぐためである。

### 認証状態の確定後の遷移
- `auth.onAuthStateChanged` のコールバックが発火し、認証状態が確定した時点で `global-loader` の `.active` クラスを削除する。
- 未ログインの場合：
  - `portal.html` では `auth-overlay` などのログインUIを表示する。
  - その他の子アプリ画面（`pos.html` など）では、ログインUIを自体を持たず、速やかに `portal.html` へリダイレクトする。

## 7. コンポーネント別の詳細パターン

### Glassmorphism セクション (`.flow-step` 等)

- **用途**: プロセスの説明や、機能の概要を示すステップ要素に使用。
- **背景**: `rgba(255, 255, 255, 0.8)` 程度の透明度。
- **エフェクト**: `backdrop-filter: blur(10px)` による背景ぼかしを必須とする。
- **インタラクション**: ホバー時に `translateY(-8px)` のリフトアップと、影の強調を行うことで「プレミアム感」を演出。
- **境界線**: `rgba(255, 255, 255, 0.4)` の細い境界線。

### アコーディオン形式のスライドカード (リアルタイム情報UIなど)

- **用途**: 限られたスペース（モバイル画面幅等）で複数のカードを並べ、特定の一つを拡大表示（フォーカス）する際に使用。
- **レイアウト方針**:
  - `display: flex` と `overflow-x: auto` を活用した横スクロールレイアウトを基本とする。
  - 通常時は各カードを等分幅（例: `flex: 0 0 calc(33.333% - 8px)`）で表示。
  - 拡大対象（`.expanded` 等）は幅を大きく（例: `flex: 0 0 85%`）し、他を自動的に端へスライド・退避させる。
- **UX向上策**:
  - `scroll-snap-type: x mandatory` を指定し、スワイプやクリック時の拡大後に要素が画面中央にスナップするようにする。
  - `transition` プロパティ（`flex`, `transform`等）を用いて滑らかな拡大・縮小アニメーションを提供する。
  - タップで元の状態に戻るためのロジック（トグル動作）を付与する。

## 9. ローディング・待機表現

### 標準スピナー
- **方針**: 以前の複雑なアニメーション（ぽよんぽよんする円など）を廃止し、標準的な円形スピナー（`border-radius: 50%` + `border-top-color` の回転）へ統一した（2026-04-19）。
- **理由**: ユーザーが「処理中であること」を瞬時に理解できるよう、慣習的なデザインを採用。また、CSS負荷を抑え、低スペック端末でのカクつきを防止する。

### 全面ローダー (`#global-loader`)
- 画面遷移や初期化時に使用。
- ローディング中もユーザーの不安を軽減するため、進行状況に応じたテキスト（「Loading...」「認証を確認中...」など）を添えることが望ましい。

## 11. 管理者ツールのUI方針 (Admin Tool UI)

### 究極のミニマリズム (2026-04-20 導入)
- **背景**: 複雑な装飾（グラデーション、グラスモーフィズム等）は、開発速度の低下や予期せぬレイアウト崩れ、JavaScriptとの競合を引き起こす原因となる。
- **方針**: 実行委員やスタッフが使用する管理画面（`venue.html` 等）においては、プロジェクト標準の `style.css` すら適用せず、**完全に独立した最小限のインラインスタイル**での構築を許容する。
- **視覚的特徴**:
  - 白背景（ダークモード時は黒）に黒文字のソリッドな配色。
  - 装飾を排した実線ボーダー、等幅またはシステムフォント（`system-ui`）の使用。
  - アニメーションの全廃。
- **メリット**: ブラウザのレンダリング負荷を最小限に抑え、スクリプトの実行順序や外部アセットの読み込み遅延に左右されない、極めて堅牢な操作画面を提供できる。

## 12. 技術ドキュメントの図面基準 (Technical Documentation Diagrams)

### 印刷・PDF出力への対応 (2026-05-09 導入)
- **背景**: PlantUML や Mermaid で作成された図面が、印刷時やPDF変換時に右端が切れてしまう問題が発生した。
- **PlantUML の基準**:
  - すべてのシーケンス図およびアーキテクチャ図において、`@startuml` の直後に `scale` 指定を行うことを原則とする。
  - **サイズ調整**: `scale 800 width` を指定し、A4の横幅に固定する。全体的な縮小率（`scale 0.5`等）は文字が小さくなりすぎるため避ける。
  - **可読性向上**: `skinparam defaultFontSize 14` を追加し、図の中の文字を標準より大きく保つ。
  - **横幅の抑制**: `skinparam maxMessageSize 80` を追加し、メッセージを積極的に折り返させることで、文字が大きくても図が横に膨らまないようにする。
  - **全体構成図**: 主要パッケージを縦並び（`-[hidden]down->`）に強制して横幅を削減する。
- **Mermaid の基準**:
  - 原則として `flowchart TD` (Top-Down) を使用し、横方向への分岐が増えすぎないように調整する。
  - 初期化ディレクティブ `%%{init: {'theme': 'base', 'themeVariables': { 'fontSize': '12px' }}}%%` を追加し、可読性を維持する。
  - ノード内のテキストが長い場合は、`<br/>` による改行を積極的に活用し、ノードの幅を抑える。

## 13. グローバルフッターおよびアンケートバナー (2026-05-22 実装)

### 概要

`app-shell.js` の `injectFooter()` / `injectHeader()` により、指定された**ホワイトリスト対象ページ**にのみ動的挿入されます。

### 適用対象ページ（ホワイトリスト）

- `404.html`, `about.html`, `about-us.html`, `account.html`, `detail.html`, `index.html`, `map.html`
- `mobile-order-guide.html`, `projects-list.html`, `stage-list.html`, `terms.html`, `pos/status.html`

### アンケートバナー（`.survey-banner`）

- ヘッダーの直前に挿入（`insertAdjacentHTML("beforebegin", ...)`）。
- グラデーション背景（`var(--primary-gradient)`）、左右2枚のリンクカード。
  - 左: コンピュータ科学部アンケート（Googleフォーム）
  - 右: 生徒会人気投票（暫定: `404.html` → URL確定次第 `app-shell.js` の `voteUrl` を更新）

### フッター（`.app-footer`）

- ボトムナビ（`.app-bottom-nav`）の直前に挿入。
- `padding-bottom: calc(var(--bottom-nav-height) + var(--safe-area-bottom))` でボトムナビと重ならない設計。
- **サイトマップ（`.footer-sitemap`）**: 4カラムグリッド。レスポンシブで700px以下は2カラム、380px以下でも2カラム維持。
- **アンケートカード（`.footer-survey-card`）**: ホバーでprimary-colorのボーダー＋浮き上がり。
- **巨大ロゴ（`.footer-biglogo`）**: `font-size: max(4rem, 22vw)`（高さ制限なし）、`scaleX` でwrapに合わせてフィット。
  - `'26` 部分は `.glow-26` で `pulse-26` アニメーション（紫グロー）。
  - クリックで全文字を `.char` スパンに動的分割し、`char-wave` キーフレームで順次ウェーブアニメーション。
- **SNSリンク（`.footer-sns-btn`）**: GitHub（ホバーで黒系）、Instagram（ホバーで `#e1306c`）のアイコンボタン。背景透明・ボーダーのみ。
- **コピーライト（`.footer-bottom`）**: 「© 2026 コンピュータ科学部」および横浜南陵高等学校の明記。

## 14. 利用規約違反・アカウント停止画面 (`main/banned.html`)

学校祭の来場者・生徒が不正利用（注文放置等）を行った際のBAN画面仕様。

### 演出・ビジュアル仕様
- **手描き風の動く「目」**:
  - Canvas APIで手描きアニメーション風のノイズ（ボイリング）を含んだ「目」を描画。
  - 初期ロード時に「瞬き（まばたき）してから見開く」目が覚める演出を実装。
  - 最初期のセリフ（`lineIndex <= 1`）の時は視線がキョロキョロと彷徨い、それ以降（`いるんですね。`以降）は中央（ユーザー）を凝視（ガン見）する。
  - 選択肢表示中は下部（選択肢の方向）を凝視する。
- **目の表示・非表示の動的制御**:
  - 語り手の問いかけ内容（「誰も来ないとわかった頃」などの絶望や虚無を伝えるタイミング）に応じて、目がすっとフェードアウト（非表示）し、不穏な空気を演出する。
  - 目のフェード（不透明度）切り替えは、CSS of `transition: opacity 0.8s` でスムーズに動作させる。
- **目の色と瞳孔の動的制御**:
  - グリッチセリフ時、瞳孔が縮小し、目全体が細かく震え、色が血のような赤色にじんわり変化する。
  - 赤強調セリフ時、瞳孔が拡大し、色が血のような赤色にフェード変化する。
  - 色変化は、瞬間切り替えではなくRGB補間（`currentColorFactor`）によりじんわり赤く染まるフェードイン・アウト演出。
- **タイピングとレイアウト**:
  - 文字の表示速度は `120ms` / 文字 に調整。
  - タイピング時のカーソル（`_`）には、`width: 0` と `transform: translateX` を採用し、タイピング完了時の文字のガクつき（レイアウトズレ）を完全に排除。
- **シナリオ制御**:
  - 注文放置による精神的ダメージを淡々と語りかける演出。
  - 二択の問いかけ（忘れてた/用事ができた/……）の後に「そうですか。そうですか。」と続き、最後までゴミ袋の話やアカウントのゴミ袋行き、そして「永遠にさようなら」と語りかけてから目のCanvasを完全に消去し、システム警告へと遷移する。
  - 選択肢表示の直前の二重クリック等により進行がフリーズ（選択肢自動遷移タイマーの競合）しないよう、進行処理（`nextLine`）実行時に自動遷移タイマー（`choiceTimeout`）を確実にクリアするガード処理を組み込んでいる。



### トップページ ガントチャート
- 各企画のバーをタップした際は、吹き出し（ツールチップ）形式のポップアップ（すりガラス効果/Glassmorphism）をバーの直下に表示し、概要を提示する（v0.3.35）。
- スクロール領域（`chartWrapper`）の端で吹き出しが見切れるのを防ぐため、要素を `document.body` 直下に移動させて配置し、Viewport基準の絶対座標で位置を計算（左右端からはみ出さないようクランプ）する。
- 吹き出し本体の位置クランプによるズレを相殺するため、CSS変数（`--arrow-left`）を介して、矢印部分（`::after`）の位置を動的に調整する。また、縦スクロール領域が不要に広がるのを防ぎ、かつ位置ズレを防止するため、ガントチャートの横スクロールおよび画面全体のスクロール発生時にはポップアップを自動的に非表示にする（v0.3.36）。
- 横スクロール時に「場所」列がズレる不具合を解消するため、中間ラッパーである `.gantt-header` および `.gantt-row`（`display: contents`）を廃止し、すべてのセルを `.gantt-chart` 直下にフラットに並べるグリッド構造へと刷新（v0.3.44）。さらに、横スクロール時に場所列が包含ブロック制限（`grid-column: 1`）によって左に消え去る問題を解決するため、場所列要素を `grid-column: 1 / -1`（グリッド全幅）に配置し包含ブロックを最大化、CSSで `width: 120px` を固定した。これにより、どれだけ横スクロールしても場所列が左端に完全に固定され、他の時間セルが下に潜り込む仕様に改善した（v0.3.45）。
- 現在時刻インジケーター（`#current-time-indicator`）の追加先を外枠からグリッド本体（`.gantt-chart`）に変更し、`.gantt-chart` に `position: relative;` を追加。これにより外枠の `padding` による表示位置のズレ（左に20pxズレる現象）を解消し、正確な時間に赤いバーが描画されるように修正した（v0.3.44）。
- `.gantt-time-header` と `.gantt-place-header` にも `position: sticky; top: 0;` を付与し、縦スクロール（またはスマホ幅で両方向にスクロール）した際も、時間が上部に固定されるようにした（v0.3.44）。
- タイムテーブルの時間軸を従来の 16:00 から後夜祭に対応するため 18:00 まで延長。JavaScript内の `timeHeaders` の定義を拡張するだけで、表示幅、時間セル数、および現在時刻インジケーターの検知範囲が自動的に 18:00 まで追従スケーリングされる（v0.3.45）。

## 15. POS / モニター画面におけるiPad全画面・表示最適化仕様 (v0.5.67 ~ v0.5.70)

### 全画面化とメタ設定
- **メタタグの統一**: 全てのPOS関連画面 (`pos.html`, `presenter.html`, `kitchen.html`, `monitor.html`) にて、SOKと同様に以下のメタタグを必須とする。
  - `<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover" />`
  - `<meta name="apple-mobile-web-app-capable" content="yes" />`
  - `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent" />`

### ステータスバー・ネイティブUIとの被り防止
- **OSステータスバー被り対策**: iPadで全画面表示にした際、上部ステータスバー（時刻・バッテリー％）や左上のSafari全画面「×」ボタンとアプリUIが重ならないよう、`.top-bar` または各画面ヘッダーに適切な内側余白（パディング）を設定する。
  - `pos.html`: `padding: max(16px, env(safe-area-inset-top)) 40px 8px 100px;`（左100px、右40px、上16px以上）
  - `kitchen.html` / `presenter.html`: `padding: 12px 20px 12px 80px;`

### ローディング停滞時のフォールバックUI
- **起動時タイムアウト**: 初回アクセス時や再読み込み時に、Firebase初期化・認証の停滞によってローディング画面（`#global-loader`）が解除されない場合に備え、起動から8秒後に「ポータルへ戻る」リンク（`#loader-fallback`）を表示する。
- **誤表示防止制御**: 認証完了時（`hideLoader()`）に `clearTimeout` で8秒タイマーを解約し、`loader-fallback` を非表示化する。さらに、注文送信や決済中などで呼び出される通常の `showLoader("注文送信中...")` 内でも `loader-fallback` を強制的に非表示に設定し、通常操作中にポータルへの戻りボタンが表示される誤動作を防止する。

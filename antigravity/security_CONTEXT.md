## 2. 是正仕様変更の3大原則

1. **ゼロトラスト防御と多層防御 (Defense in Depth)**:
   クライアント・通信経路・ローカル環境を一切信用せず、Rules/Functions/UIの全レイヤーで多層検証を徹底する。
2. **完全性と可用性の両立 (Integrity & High Availability)**:
   トランザクション排他ロックで二重注文・価格改ざんを根絶しつつ、日次カウンター循環採番や公開プロキシ分離により、混雑ピーク時も無停止で高スループットを維持する。
3. **現場リアリズムと人的フェイルセーフ (Human-in-the-Loop Resilience)**:
   動的認証UIによる商品横取り防止、冤罪自動BANを防止するスタッフ確認型モデル、キオスク端末のiOSアクセスガイド施錠を徹底する。

## 3. 無停止移行の4段階ロールアウト手順

`mermaid
graph LR
    P0[Phase 0<br/>管理サーバー隔離<br/>シークレット除去] --> P1[Phase 1<br/>Functionsロック<br/>プロキシ先行展開]
    P1 --> P2[Phase 2<br/>フロント・KDS改修<br/>動的認証UI導入]
    P2 --> P3[Phase 3<br/>Rules呼出全公開廃止<br/>5MB/CSPヘッダー適用]
    P3 --> P4[Phase 4<br/>現場iPadアクセスガイド<br/>受渡ロールプレイング]
`

今後の実装作業は、必ずこのフェーズ順（Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4）に従って段階的に適用し、各ステップでの自動テストおよび検証を実施すること。

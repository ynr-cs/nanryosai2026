# 🗺️ 2Dキャンパスマップシステム (V3 Leaflet版) 完全技術仕様 & 運用マニュアル

## 1. 概要・設計思想・採用経緯

南陵祭2026の公式Webサイトにおける中核機能の一つであるインタラクティブ・キャンパスマップシステム（V3）の技術仕様・アーキテクチャ・運用保守マニュアルです。

### 1.1 採用経緯と3Dマップからの転換
初期検討段階では Three.js による 3D キャンパスマップが試作されましたが、**校舎の3Dモデリングや空間構築にかかる膨大な制作時間・工数に対し、得られる実用上のメリットが小さくコストパフォーマンスが見合わない**ため、本番採用は見送られ 2D Leaflet.js V3 へ移行しました。

国土地理院の航空写真タイルを活用することで、テクスチャ作成にかかる時間をゼロにし、実用的な屋内フロア案内や企画検索のUI/UX向上にリソースを集中させました。

> [!NOTE]
> 本システム（V3）は現在**「基礎設計と主要機能の検証を終えた試作段階（プロトタイプ）」**です。現地寸法との実測キャリブレーションやUI微調整など、今後改善・修正すべき課題が多数存在します。

### 1.2 コア設計思想
- **Zero-Remote-Database 原則**: Firestore やバックエンド API への問い合わせを一切行わず、静的な JSON と Vanilla JavaScript のみで動作。ネットワーク遮断時や高負荷時にもダウンしない絶対的可用性を実現。
- **実座標（EPSG:3857）準拠**: 国土地理院（GSI）のシームレス空中写真タイルと実測緯度経度を完全に一致させ、現実の校舎位置と直結。
- **Mobile First & Glassmorphism**: スマートフォンでの片手操作を最優先に設計された縦型フロアピル、3段階スナップ式ボトムシート、洗練されたグラスモーフィズムデザイン。

### 2.2 3階層 Centroid Join（重心動的結合）メカニズム
企画データと地図上の位置情報は、静的な `roomId` をキーとしてクライアントサイドで動的に結合されます。
1. **企画定義 (`main/data/data.js`)**:
   各企画（全19件）に `roomId`（例: `"room_301"`, `"room_104"`, `"tent_a"`）を付与。企画側に緯度経度は持たない。
2. **部屋幾何・スポット定義 (`main/data/campus_map_data.json`)**:
   - 屋内フロア (`indoorFloors[floor].rooms`): 教室等の多角形ポリゴン座標配列。
   - 屋外スポット (`spots`): テントや案内所等の点座標 (`latlng`)。
3. **重心計算 (Green's Theorem / Shoelace Formula with Local Origin)**:
   多角形ポリゴンの頂点列から、局所原点オフセットを適用した Green の定理により幾何重心を算出。算出した重心座標に企画カテゴリに応じたカスタムマーカーピンを自動配置。
   ※同一部屋に複数企画が存在する場合（例: 作法室の華道部＋茶道部）は、同一重心に複数企画情報がバインドされ、ボトムシート内でスワイプ閲覧可能。

## 4. 来場者UI仕様 (`main/map.html`)

### 4.1 Glassmorphism & モバイル最適化
- **背景とテーマ**:
  - ライトモード: GSI 空中写真タイルそのまま表示。
  - ダークモード (`data-theme="dark"`): CSS フィルター `filter: brightness(0.65) contrast(1.15) saturate(0.85)` を適用し、夜間・暗所での眩しさを抑えつつ、ベクター要素をネオングロー（発光表現）で鮮明化。
  - タイル読み込み前・オフライン時のフェイルセーフ背景: キャンパスグリーン (`#cfe3d8` / `#1a2e22`)。

### 4.2 コントロール部品
1. **右側スリム縦型フロアピル (Vertical Floor Switcher)**:
   - 画面右側にフロア切替ピル（5F, 4F, 3F, 2F, 1F）を固定配置。
   - 階層を切り替えると、該当階の `indoorFloors`（教室・廊下・階段・トイレ）および該当階に配置された企画ピンのみがスムーズにフェード切替。
2. **水平スクロール カテゴリフィルタチップ**:
   - `すべて`, `模擬店 🏪`, `調理販売 🍳`, `展示 🎨`, `ステージ 🎭`（南陵祭公式4大ジャンル）。
   - 選択されたカテゴリに属するピン・教室ポリゴンのみを高輝度表示（非該当は低透過度へ減衰）。
3. **3段階スナップ式 Glassmorphism ボトムシート (Bottom Sheet)**:
   - **Collapsed (約72px)**: 下部に小さく折りたたまれ、ピン未選択時は周辺案内、選択時は店舗名と最小情報を表示。
   - **Peek (約45vh)**: ピンタップ時に自動展開。企画タイトル、団体名、場所、メニュープレビュー、クイックアクションボタンを表示。
   - **Expanded (約88vh)**: 上部へスワイプ展開。企画詳細、フルメニュー、営業時間、注意事項などを全画面表示。
   - **タッチジェスチャー**: 慣性スクロール・フリック速度（Velocity）に応じたスナップ点吸着。

- **モバイルオーダー対応店 (`useMobileOrder: true`)**:

## 6. セキュリティ & 数値計算の堅牢化仕様

### 6.1 XSS (Cross-Site Scripting) 完全防御
企画データ（`data.js`）、URLクエリパラメータ（`?project=`, `?room=`）、アクセスルート名などに悪意ある HTML/JavaScript が混入しても実行されないよう、`escapeHtml` 関数を全動的 DOM 生成箇所（`innerHTML`, `L.divIcon`）に適用。
```javascript
function escapeHtml(str) {
  if (str === null || str === undefined) return '';
  return String(str)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#039;')
    .replace(/=/g, '&#061;');
}
```

### 6.2 浮動小数点桁落ち（Catastrophic Cancellation）の解消
緯度経度座標（約 35.38度, 139.58度）のようなベース値が大きい座標系において、微小ポリゴン（教室サイズ: 差分 0.0001度 程度）の Green の定理外積計算を行うと、有効桁数の減算による桁落ちが発生し、重心が 1km 以上飛散する問題がありました。
これを解決するため、**局所原点オフセット（Local Origin Offset）** を導入：
```javascript
function calculatePolygonCentroid(coords) {
  if (!coords || coords.length === 0) return CAMPUS_CENTER;
  if (coords.length === 1) return coords[0];
  if (coords.length === 2) {
    return [(coords[0][0] + coords[1][0]) / 2, (coords[0][1] + coords[1][1]) / 2];
  }

  const n = coords.length;
  // 局所原点として最初の頂点を採用
  const x0 = coords[0][0];
  const y0 = coords[0][1];

  let area = 0;
  let cLat = 0;
  let cLng = 0;

  for (let i = 0; i < n; i++) {
    const j = (i + 1) % n;
    const x1 = coords[i][0] - x0;
    const y1 = coords[i][1] - y0;
    const x2 = coords[j][0] - x0;
    const y2 = coords[j][1] - y0;

    const cross = x1 * y2 - x2 * y1;
    area += cross;
    cLat += (x1 + x2) * cross;
    cLng += (y1 + y2) * cross;
  }

  area = area / 2;

  // 面積が極小（退化ポリゴン・同一直線）の場合は単純平均にフォールバック
  if (Math.abs(area) < 1e-12) {
    const sumLat = coords.reduce((acc, p) => acc + p[0], 0);
    const sumLng = coords.reduce((acc, p) => acc + p[1], 0);
    return [sumLat / n, sumLng / n];
  }

  cLat = x0 + cLat / (6 * area);
  cLng = y0 + cLng / (6 * area);

  return [cLat, cLng];
}
```

## 8. 運用保守・データ更新手順 (Operations & Maintenance Manual)

### 8.1 企画の追加・部屋割り変更手順
1. **`main/data/data.js` の更新**:
   企画カタログに新しい企画を追加するか、既存企画の `roomId`（例: `"room_302"` や `"tent_b"`）を書き換えます。
2. **`main/data/campus_map_data.json` の確認**:
   指定した `roomId` が `campus_map_data.json` 内の `indoorFloors`（部屋）または `spots`（テント等）に存在することを確認します。
3. **E2E テストによる整合性検証**:
   ```bash
   node tests/e2e/test_runner.js
   ```
   Centroid Join で 100% マッピングされていることを自動検証します。

## 10. ピンアンカー接地最適化 & UI視覚ノイズ一掃 (v0.5.239)

### 10.1 二重オフセットバグの解明と解消
- **現象**: 1年生・2年生等の教室企画ピン全体が、教室ポリゴンの上空約56px（校舎外の空中）へ飛び出して表示されていた。
- **原因**: Leaflet の `L.divIcon({ iconAnchor: [18, 41] })` によるマージン相殺に加え、CSS の `.custom-map-pin` が `transform: translate(-50%, -100%)` を保持していたため、二重にマイナスシフトが適用されていた。
- **解決策**:
  - CSS の `transform: translate(-50%, -100%)` を完全排除。
  - ピンのDOM構造を上から「`pin-label`（頭上ラベル） → `pin-body`（丸型アイコン） → `pin-arrow`（下向き矢印針）」の順に配置。
  - Leaflet の `iconSize: [36, 41]`, `iconAnchor: [18, 41]` を設定することで、ピンの底面中央（針の先端）が教室ポリゴンの重心（`pinCoord`）に寸分の狂いもなく正確に刺さるよう整合。
  - `transform-origin: 50% 100%` により、ホバー・アクティブ時の拡大アニメーションも針の先端を支点として行われ、接地位置がブレない。

### 10.2 視覚ヒエラルキーとインフラピンのスマート化
- **企画ピン（主役）**: 鮮やかなカテゴリカラー、矢印付きの大きなピン、頭上に浮かぶ企画名ラベル。
- **インフラピン（補助機能）**:
  - AED、自販機、ゴミ箱、トイレは `26px × 26px` の丸型フラットバッジ（`isFacility: true`）。
  - 下向き矢印を排除し、中心アンカー `[13, 13]` で地点中央に配置。
  - 常時表示ラベルを完全撤去し、ホバー・タップ時のみすっきりツールチップ（`.facility-tooltip`）およびボトムシートを表示。地図全体のテキストノイズを約70%削減。

### 10.3 企画なし部屋の無駄ピン除外
- `buildJoinedPinsModel` において、企画が紐づいていない特別教室・準備室（記念室、生徒会室、化学準備室など）のピン生成を停止。
- 部屋ポリゴン自体のタップによる情報閲覧・立入禁止警告表示は維持しつつ、マップ上の無駄なピン群生を一掃。

## 11. ポリゴンクリック干渉解消 & タッチ操作性最適化 (v0.5.241)

### 11.1 背景ポリゴンの完全非アクティブ化
- **問題**: 校舎外枠ポリゴン（`buildings`）、屋外エリア（`outdoorAreas`）、廊下（`corridors`）、階段（`stairs`）、トイレ（`toilets`）が Leaflet のデフォルトで `interactive: true` になっており、画面全体がタッチイベントを吸収・横取りして地図のスクロールやピンチズームが引っかかっていた。また、触るたびに「生徒棟」「校庭」「体育館」などのツールチップが勝手にポップアップしていた。
- **対策**:
  - `buildings`, `outdoorAreas`, `corridors`, `stairs`, `toilets` の全レイヤーに `interactive: false` を指定。
  - 不要なツールチップ（`poly.bindTooltip`）を完全撤去。
  - CSS で `.outdoor-polygon, .building-polygon, .corridor-polygon, .stairs-polygon, .toilet-polygon` に `pointer-events: none !important;` を付与し、タッチイベントを地図本体へ 100% 透過。

### 11.2 企画部屋のみの条件付きクリッカブル化
- `rooms` のうち、文化祭企画が紐づいている部屋（`hasProject = true`）のみ `interactive: true` かつ `className: 'room-polygon has-project'` とし、クリックハンドラーをバインド。
- 企画のない空き教室・準備室は `interactive: false` かつ `pointer-events: none` とし、触っても意図しないシートが立ち上がらないように制御。

### 11.3 モバイルジェスチャ誤判定解消と余白タップによるシート閉鎖
- Leaflet の `tap: true` によるスマホでの誤判定（ghost clicks）を避けるため、`tap: false` を設定。
- `map.on('click')` を新設し、地図の余白をタップした際に開いているボトムシートを自動的に折りたたみ（`COLLAPSED`）、部屋のハイライトを解除する快適なUXを実装。
- ピンや部屋のクリック時に `L.DomEvent.stopPropagation(e)` を適用し、不要なイベントバブリングを完全防止。

### 15.11 ボトムシート連動ボトムナビゲーションバー自動スライド退避＆PEEK表示最適化 (v0.5.284)
- **背景/ユーザーからの至急要望**:
  - マップ上の企画ピンや教室をタップした際、ボトムシートが PEEK 状態（初期高さ約 38vh）でせり上がるが、画面最下部に固定されたフローティング・ボトムナビゲーションバー（`.app-bottom-nav`、ホーム・企画・オーダー等、高さ約 70px + 下部マージン 20px〜34px）が常時居座っているため、ボトムシート下部のアクションボタン（「モバイルオーダーで注文する」「企画の詳細情報を見る」）とモロに被ってしまい、隠れたり誤タップを招いていた。
- **解決策/実装詳細 (`main/map.html`)**:
  1. **ボトムナビバー自動スライド退避アニメーション (`.nav-hidden-by-sheet`)**:
     - `.app-bottom-nav` に `transition: transform 0.3s cubic-bezier(0.2, 0.8, 0.2, 1), opacity 0.25s ease !important;` を定義。
     - `.nav-hidden-by-sheet` クラス付与時に `transform: translateX(-50%) translateY(140%) !important; opacity: 0 !important; pointer-events: none !important;` により、画面下方向へ滑らかにスライドアウトしつつフェードアウト。誤タップを原理的に排除。
  2. **BottomSheetController の状態遷移連動 (`updateBottomNavVisibility`)**:
     - シートが `PEEK` または `EXPANDED` に遷移した際に `.app-bottom-nav` に `.nav-hidden-by-sheet` を付与。
     - シートが `COLLAPSED`（閉じる）に遷移した際に `.nav-hidden-by-sheet` を削除し、下からスッとボトムナビが復帰。
     - `snapTo(state, animated)` のコアロジック内に統合することで、タップオープン時、ドラッグ終了時（`onEnd`）、クローズボタン押下時、地図移動時など全遷移パターンで確実に連動。
     - `app-shell.js` の遅延初期化時にも安全に動作する `requestAnimationFrame` フォールバック機構を内蔵。

### 15.13 マップエディタにおける屋外販売団体（中庭テント等）・全スポットのドラッグ移動ハンドル＆座標直接編集サポート (v0.5.287)
- **背景/ユーザー要望**:
  - 管理者・運営より「マップエディタで、外の販売団体（中庭テント等）の場所を移動させたい。それができないため、マップエディタを編集して移動できるようにしてほしい」という至急要請に対応。
  - 従来の `map-editor.html` では、頂点ハンドル生成（`attachVertexHandles`）がポリゴン・ポリラインの2次元配列のみを前提としており、単一座標を持つスポット要素（`spots`、中庭テント `tent_102`, `tent_301` 等）は選択しても頂点ハンドルが表示されず、画面上でのドラッグ移動が一切行えなかった。
- **実装詳細 (`main/admin/map-editor.html`)**:
  1. **スポットドラッグハンドルの提供 (`attachVertexHandles`)**:
     - `layer.feature.properties` の `entityType === 'spot'` または単一座標要素を判定。
     - スポット位置（`layer.getLatLng()` または `latlng` / `coordinates`）に、視認性の高いオレンジ丸ドラッグハンドル（`L.marker`、直径22px、白枠、ドロップシャドウ、十字矢印アイコン `fa-arrows-up-down-left-right`、cursor: move）を生成。
     - `dragstart`: マップ全体のパン操作を無効化（`this.map.dragging.disable()`）。
     - `drag`:
       - 移動先座標を小数第6位で取得。
       - スナップ有効時は最近傍頂点スナップ（12px）を自動適用。
       - `feature.latlng` および `feature.coordinates` を更新。
       - 元レイヤー（`layer.setLatLng(moveLatLng)`）とメモリ上データエンティティ（`layer._entityRef` / `findMapDataEntity`）をリアルタイム同期。
       - インスペクターの座標表示（`updateCentroidDisplay`）をリアルタイム更新。
     - `dragend`:
       - 地図ドラッグを再有効化（`this.map.dragging.enable()`）。
       - `this.history.pushState(this.mapData, 'スポット移動: ...')` による Undo/Redo 履歴の記録。
       - `this.triggerAutoSave()` による自動保存。
       - トースト通知（`📍 スポット [〇〇] を移動しました`）の表示。
       - `this.attachVertexHandles(layer)` によるハンドルの位置再同期。
  2. **プロパティインスペクターでの座標直接編集サポート**:
     - HTML の座標入力欄（`#fieldPinLat`, `#fieldPinLng`）の `readonly` 属性を解除し、`type="number" step="any"` に変更。
     - スポット選択時はラベルを「スポット座標 (緯度・経度) 📍」に動的切り替え、不要な重心計算ボタンを自動非表示化。
     - 入力欄の `input` / `change` / `Enter` キー押下ハンドラーにより、数値を直接入力して即座にスポット座標を更新・レイヤー位置とハンドル位置を再同期・Undo履歴保存。
  3. **安全ガード強化**:
     - 通常ポリゴン・ポリラインの頂点編集において、1次元座標配列が渡された場合に NaN ループでクラッシュしないよう配列構造チェック（`Array.isArray(coords[0])`）を強化。

### 15.15 マップエディタにおけるスポット直接ドラッグ対応＆調理団体向けリッチビジュアル化 (v0.5.290)
- **背景/ユーザー要望**:
  - ユーザーから「マップのスポットドラッグがうまくいかない。調理団体のドラッグだから、ちゃんと動くようにしてほしい。それで反映されるようにしてほしい」との至急要請に対応。
  - `main/admin/map-editor.html` において、中庭テント（`tent_102`, `tent_301` 等）などの調理団体（スポット）が `L.circleMarker`（半径7pxの極小円、draggable不可）で描画されていたため、ユーザーが地図上のスポットを直接掴んでドラッグ移動しようとしても地図がパン（スクロール）してしまい動かない問題が発生していた。
  - また、調理団体が単なる緑色の小丸で常時ラベルやアイコンが見えず、どのテントがどのクラス・品名（ソーセージ、カステラ、焼き鳥等）か直感的に識別できなかった。
- **実装詳細 (`main/admin/map-editor.html`)**:
  1. **スポットマーカーの直接ドラッグ（`L.marker` / `draggable: true`）全面刷新**:
     - `L.circleMarker` を廃止し、直接ドラッグ可能な `L.marker` に刷新。
     - アイコン作成ロジック:
       - 調理団体（テント等）は直径28pxのアンバー・オレンジグラデーションピン（`#f97316`〜`#ea580c`）、2px白枠、シャドウ、調理器具アイコン `fa-utensils` またはテント `fa-campground`。
       - 一般スポットは直径28pxのエメラルドグリーングラデーションピン（`#10b981`〜`#059669`）、2px白枠、シャドウ。
       - 常時見やすいラベルバッジ（`.spot-label-badge`）: フォント11px、白背景、角丸、太字、ドロップシャドウ。調理団体はクラス・品名をスマート抽出して `⛺ 3-1 カステラ`、`⛺ 1-2 ソーセージ` 等を表示。非選択時でも一目で判別可能。
       - カーソル: `cursor: grab`、ドラッグ中 `cursor: grabbing`、拡大アニメーション。
     - 直接ドラッグイベント（`dragstart`, `drag`, `dragend`）のバインド:
       - `dragstart`: `this.map.dragging.disable()` で地図パンを無効化、未選択時は即時選択（`this.selectFeature(marker)`）。
       - `drag`: スナップ処理（12px）適用、座標更新（`latlng` & `coordinates`）、インスペクター表示リアルタイム追従（`updateCentroidDisplay`）、選択ハンドル（`vertexHandles`）の位置同期。
       - `dragend`: `this.map.dragging.enable()` で地図パンを復帰、座標確定、Undo/Redo履歴記録（`this.history.pushState`）、オートセーブ（`this.triggerAutoSave`）、ハンドル再配置（`this.attachVertexHandles`）、トースト通知。
  2. **選択時のオレンジ十字ハンドル（`attachVertexHandles`）とのダブルドラッグ両立**:
     - マーカー直接ドラッグだけでなく、クリックして選択した際に出るオレンジ十字ハンドル（`editorHandlePane`）からのドラッグ移動も完全サポート。
     - どちらをドラッグしてもマーカー本体・データ実体・インスペクターが100%確実に同期・保存されるアーキテクチャを確立。
  3. **プロパティインスペクターでの座標直接入力の確実な連動**:
     - `#fieldPinLat`, `#fieldPinLng` の数値直接入力時（Enter/change）にも、`marker.setLatLng()`、`mapData.spots`、ハンドル位置が即座に同期されることを保証。
- **得られた知見**: 地図上の要素編集UIでは、「一度クリックしてハンドルを出してからドラッグする」という2段階操作は直感性に欠け、ユーザーは要素そのものを直接掴んで動かそうとする。要素自体を直接 `draggable: true` としつつ、選択ハンドルとの双方向同期を持たせることで、あらゆるメンタルモデルのユーザーがストレスなく直感的に編集できる。
